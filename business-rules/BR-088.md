# BR-088 · Without an encryption key, connections are unavailable and nothing is decrypted

## Rule

When the connections key is absent, unreadable, invalid or different from the database's (key check), each connection is seen as `clé indisponible`, no token is decrypted or returned, no encrypted value is written and no state is changed by the gateway, and the gateway stays ready; recovery is seen at the next request.

## Clarifications

- Reading B of decision C2 c (hypothesis H1, §9): `/readyz` does not change (BR-033 unchanged), the inbound side does not need the connections.
- **Key check**: HMAC-SHA256(key, fixed constant), truncated to 16 bytes, written to the database in the transaction of the first ciphertext. A key of the right format whose key check differs (regenerated secret, backup restored on another instance) is treated as absent: nothing is decrypted, written or erased by the gateway, and the audit and `status` say `key_different`. Without this guard, "decryption impossible" would read as "invalid token" and would empty the library.
- A ciphertext that does not authenticate under a key whose check passes (isolated row, AAD of BR-087) is a typed and audited `access_integrity_error`, never a state transition.
- Commands allowed and refused without a key: closed list of §3.2. "No encrypted value written" does not prevent the explicit erasure requested by `revoke` or `remove` (BR-095, BR-075).
- `clé indisponible` is audited once per (connection, reason) as long as the reason does not change (review 417, m2); the marker lives in a separate table (`key_alert`), the connection's row is not touched, and recovery of the key erases it.
- Lost key: a database whose key check is set refuses any other key, even with no live ciphertext. Recovery gesture: `python -m hullgate.keys connections-key-forget --confirm`, refused as long as a ciphertext lives (connection, application with secret, open authorization), which forgets the key check; the next key is adopted at the first ciphertext (runbook `keys-and-upstreams.md`, step C12; review 417, o1).
