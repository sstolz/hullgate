# BR-316 · A request body is read within 30 seconds, then the caller is checked again

## Rule

On both listeners, a request body not received in full within 30 seconds of its first byte being awaited gets 408 `request_timeout` and the connection is closed; an authorisation decided before the body is checked again before the request acts.

## Clarifications

- The 30 seconds are a constant: no option changes them. One monotonic deadline covers the whole body, not each chunk, so a client trickling bytes cannot extend it.
- Access point: the 408 is audited `access.body_refused`, reason `request_timeout`, with the actor, as BR-311's 413 is. The token is checked again after the body: a token revoked during the read gets its BR-055 refusal.
- Admin API: a mutation checks the session again, and fresh authentication where the route needs it, inside its deciding transaction, once the write lock is held. A sign-out during the body read or the lock wait gets 401 `unauthenticated` and changes nothing. One exception: recording a provider outcome already obtained needs admission only, so a completed remote revocation is never lost.
- F-016 §3.15 lists 408 among the admin API's statuses.
- Public listener, OAuth routes (`authorize`, `consent`, `token`, `revoke`, `register`, POST): the 408 carries `request_timeout` as the `error_description` of an RFC 6749 `invalid_request` on `token`, `revoke` and `register`, and as the HTML error page on `authorize` and `consent`; it is audited under the route's action, reason `request_timeout`, actor `anonymous`. No authorisation is decided before their body, so none is checked again.
