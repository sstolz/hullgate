# BR-127 · An upstream 401 before any content is reported then retried once, for an OAuth connection only

## Rule

When the upstream answers 401 to a call before any content, the relay calls `signal_refusal` with the generation of the `Accès` used, then, for an OAuth connection only, replays the call **once** with the token that `get_access` then returns; a second 401, or any 401 on a provided-token connection, returns `connection_reauth_required` without a new attempt.

## Clarifications

- The retry applies only to a 401 response received **before any content**: the upstream refused the authentication, it did not run the tool. Any other uncertain outcome follows BR-117.
- Separate from BR-114 (which fixes the token source, `strict`): a change to the retry policy does not touch the isolation rule.
- A 401 on a provided-token connection calls `signal_refusal`, so the connection moves to `réauthentification requise` (BR-085, F-006): Q5, H10, H22 (confirmed at the freeze). The `last_reason` of the state says "mcp_refusal_401", distinct from a refusal by the OAuth provider, so that the operator knows what to fix.
- A second 401 on the fresh token triggers BR-128.
