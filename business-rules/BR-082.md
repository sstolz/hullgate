# BR-082 · Outbound authorization requires PKCE S256 and a single-use `state`

## Rule

Every outbound authorization uses the authorization code flow with PKCE S256 and a random `state` bound to the authorization opened by the CLI or the console, single-use and expiring in 10 minutes; the `redirect_uri` sent at opening and at exchange is the one chosen at opening (application URI, or BR-216's); a response whose `state` is unknown, already used or expired is refused without exchanging the code.

## Clarifications

- B1 b: the CLI displays the URL; the operator passes the return URL to `connection authorize --callback -` on standard input (BR-086: it carries the code). The `redirect_uri` is the application's (§3.1, `http://127.0.0.1/oauth/callback`), or BR-216's from the console: the authorization URL and the code exchange carry the same value.
- "No new route" of the first clarification of v2 ends here: BR-216 is that route.
- `resource` (RFC 8707) is sent according to the service's model (§3.1): for `generic`, only when the RFC 9728 discovery found a value, kept in the record (BR-097).
- The `state` is consumed in a short transaction **before** the code exchange. An exchange that fails afterwards (BR-092, BR-093) requires a new `reauthorize`; two concurrent `authorize` calls on the same `state`: the second is refused as "already used". A return carrying `error=` (for example `access_denied`) consumes the `state`, answers code 2 with the `error` code alone, leaves the connection in its state and is audited without the URL.
- `en attente` lasts until `authorize`, `reauthorize` or `remove`; the `state` expires on its own after 10 minutes, the connection remaining `en attente`. `reauthorize` from `en attente` replaces the open authorization and makes the old `state` invalid (at most one open authorization per connection). `get_access` on an `en attente` connection returns `access_not_authorized` (§3.3).
- `reauthorize` on an `active` connection opens an authorization without touching its tokens, which stay served until the exchange succeeds; they are then replaced and the old ones revoked on a best-effort basis. The account obtained is compared with the recorded account (BR-096).
