# BR-110 · A tool's public name is `<préfixe>__<outil>`, stable from one list to the next

## Rule

The public name of a tool is its connection's prefix (BR-076), two underscores, then the upstream name with the characters outside `[A-Za-z0-9_-]` replaced by `_`; the public name has **at most 64 characters**: if `<préfixe>__<nom nettoyé>` exceeds that, the upstream part is truncated to 64 − prefix length − 2 − 9 characters, then suffixed with `_` and 8 hexadecimal digits of the SHA-256 of the original upstream name; in case of a collision between two upstream names, the second receives that same suffix (truncation included); the assigned name is written at the first announcement and never recomputed, so that a tool keeps its public name as long as its connection exists, even when absent from an intermediate list.

## Clarifications

- The table (connection, upstream name → public name) is the source; the algorithm serves only for the first assignment. A future change of algorithm renames nothing.
- An upstream name repeated in one list counts only once (the first definition).
- At most 1,000 names are kept per connection; beyond that, that connection's list is treated as unavailable (BR-111, reason "too_many_names", distinct from an outage).
- Remedy: `connection tools <c> --role <chemin> --purge-names --confirm <c>` erases from the table the names absent from the upstream's current list (the names present keep theirs); the operation is audited with the actor and the number of names erased. An erased name that returns receives a new name, stable afterward. It is not played without a current list (connection down or beyond BR-109's ceiling: refusal, code 2).
- An empty upstream name, or one reduced to `_` after cleaning, is ignored and audited (reason "invalid_name").
- The uniqueness of the public name is that of (connection, public name): between connections it follows from the prefix, unique per organisation (BR-076) and without `_`. The table does not carry the organisation (out of scope, HULL-42).
- A connection's table is erased with it (BR-075); the prefix no longer changes once a placement exists (BR-076), so the name does not vary.
- The prefix contains no `_`: the first `__` unambiguously separates prefix and tool. The relay nevertheless relies on the table, never on a split of the name.
- 64 characters for the **whole** name and `[A-Za-z0-9_-]` come from the Anthropic API's constraint on tool names (`^[a-zA-Z0-9_-]{1,64}$`); not measured on the clients (HULL-3: name length open), nor the case (`Foo` and `foo` are two public names that a client folding the case would confuse), H5. With a prefix of 8 characters, the upstream part has 54 characters, or 45 plus the suffix when truncated.
