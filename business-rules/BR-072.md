# BR-072 · The database keeps no bearer secret in clear

## Rule

The database contains no authorization code, renewal or operator token in clear, only their SHA-256 fingerprint, and no JWT access token, only its `jti`; an issued value found as is in a table fails the test.

## Clarifications

- No **inbound** client secret exists (public clients, BR-061): the database keeps none, and the sweep checks that no column and no inbound dynamic registration response carries one. Upstream secrets (connection tokens, application secrets) are encrypted envelopes (BR-087, F-006), the only secret columns admitted (`application.secret_enc`, `connection.tokens_enc`, `pending_auth.verifier_enc`).
- Carried over from R-06 (fingerprints); the backup (BR-038) therefore carries no usable value, the connections key staying outside the database (BR-032 v3).
