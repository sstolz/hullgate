# BR-026 · The Python POC meets the known v1 core requirements

## Rule

The Python POC meets the v1 core requirements identified on the Go POC (#7): N1 — the access token carries the `client_id` claim (RFC 9068 §2.2); N2 — a token without the `mcp` scope is refused at the access point with `403` and `WWW-Authenticate: Bearer error="insufficient_scope"` (RFC 6750 §3.1); N4 — a role deleted then recreated under the same identifier leaves no access or renewal token issued before the deletion valid; N13 — `POST /revoke` without a `token` parameter answers `400 invalid_request` (RFC 7009 §2.1). A requirement not met is a costed gap (line H-9), carried in the comparison and **outside** the sum of BR-023, as for the Go POC.

## Clarifications

- N2: the scope is carried by the `scope` claim (RFC 9068 §2.2.3, space-separated string); token forged by the adapter with the test key, with only `mcp` removed from `scope` (one property, BR-014 discipline); positive check: the reference token, re-signed, is accepted.
- N4: played on a dedicated role, created by the adapter (`clone_profile`), so as not to touch the acceptance run's roles; access and renewal tokens issued, deletion, recreation under the same identifier; expected: 401 at the access point and `invalid_grant` at renewal.
- These are not isolation lines (H9).
- Outside the sum: operator ruling at the F-003 freeze (2026-10-28), which prevails over the sentence "counted in the sum of BR-023" of the frozen text of §4 (corrected at extraction, see spec §13).
- Reason: the comparison looks for what is done better elsewhere; a requirement that the Python building block meets without code is a "Python better" of BR-024.
