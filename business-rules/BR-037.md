# BR-037 · An mcp SDK version enters only when the bench's v1 target has replayed it

## Rule

The gate refuses an `mcp` SDK version (packages `mcp` and `mcp-types`) that is not the one of a conclusive full replay of the isolation bench's `v1` target recorded in the repository (condition 2 of ADR-001): a replay is conclusive when its evidence is neither a development nor a partial run and every test of the recipe and every control it records has passed.

## Clarifications

- The evidence read is `poc/isolation-bench/evidence/results-v1.json`. The guard reads verdicts only (`tests[].result`, `controls[].result`); the v1 readings of T06 to T10 and BR-015 (`meta.lectures_v1`, `mapping.json`, AC-29 of F-008) belong to the bench (BR-071) and are not known to the guard.
- Freshness is out of the rule: the guard reads the SDK version and the verdicts, not `bench_commit`, `source_dirty`, `config_dirty`, any lock fingerprint or the gateway sources. A gateway, Dockerfile or other-dependency change does not require a replay under this rule; the gateway is judged by BR-071 when a feature closes. `bench_commit` cannot be followed through squash-merged history in any case.
- Upgrade procedure (README and `make bench-sdk`): change `mcp==X.Y.Z`, `uv lock`, commit, `./bench.sh --target v1 --purge-images` (conclusive, never `--dev`) run in the toolbox, commit the evidence, PR. The N3 and nominal `/revoke` harnesses run inside that pass and are checked by the guard.
- State at v2: root lock and evidence both say `mcp` and `mcp-types` 2.3.0 (`bench_commit` `56cb4e3`); v2 is born conforming.

## Examples

- **Given** `pyproject.toml` pins `mcp==2.4.0`, the lock resolves it, and `results-v1.json` still records 2.3.0
- **When** `make gate` reaches `sdk-guard`
- **Then** it ends `GATE: KO sdk-guard` and names `mcp: v1 uv.lock 2.4.0, bench 2.3.0`.

### Version 1 — from 2026-10-28 to 2026-10-31

**Rule** — The gate refuses an `mcp` SDK version (packages `mcp` and `mcp-types`) that is not the one of a conclusive replay of the isolation bench recorded in the repository (condition 2 of ADR-001).

**Clarifications**
- Upgrade procedure (README and `make bench-sdk`): change the version in the v1's `pyproject.toml` **and** in `poc/py-gateway/`, `uv lock` in both, `./bench.sh --target py-gateway` (conclusive, not `--dev`), commit the evidence, PR. As long as the core (HULL-7) has not made the v1 a bench target, the `py-gateway` target (POC built on the new version) is the witness; the core replaces the target the guard reads.
- The controls outside the acceptance run (N3 and nominal `/revoke` harnesses, T10) are replayed at each upgrade and cited in the PR (reading in review); the guard reads only `results-py-gateway.json`.
- Current state: the POC's `uv.lock` and the evidence both say `mcp` and `mcp-types` 2.3.0 (`bench_commit` `a8faea7`); the v1 is born conforming.
- Consequence: `poc/py-gateway/` and `poc/isolation-bench/` stop being disposable; they are kept and maintained as the witness until the core makes the v1 the bench target. Deleting them fails the guard.
