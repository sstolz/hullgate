# BR-092 · A definitive provider refusal puts the connection in the reauthentication-required state

## Rule

A response that the table below classifies as permanent (including `invalid_grant`, revocation at the provider, the refused scope and the new consent required) places an OAuth connection in the `réauthentification requise` state; in this state no token is returned and no renewal is attempted until a `connection reauthorize` followed by a successful `authorize`, or for a provided-token connection until `connection reauthorize --file` (BR-085).

## Clarifications

- Source: spec l. 631-632. A revocation at the provider reads as `invalid_grant` at renewal, or arrives through `signal_refusal` (§3.3) on an upstream 401, which causes the renewal.
- **Closed classification of responses** (code exchange, renewal; shared with BR-093). The audit reason and the CLI message carry only the `error` code, never the body nor `error_description`.

| Provider response | Outcome | Effect |
|---|---|---|
| `invalid_grant`, `invalid_scope`, `consent_required`, `interaction_required`, `login_required` | permanent | `réauthentification requise` |
| `invalid_client`, `unauthorized_client` | permanent, reason `application` | `réauthentification requise`; `status` names the application to redeclare or reregister (reauthorizing alone is not enough) |
| `expires_in` ≤ 60 | permanent, reason `expiry_too_short` | `réauthentification requise` (BR-091) |
| failure before the request is completely sent (DNS, connection, TLS), 5xx response, 429 | transient | state and token unchanged, `access_temporarily_unavailable` (BR-093, BR-094) |
| request sent, response absent or not written (10 s deadline, cut, write impossible) | uncertain | same, outcome audited (BR-090) |
| any other response: other 4xx, malformed JSON, response > 256 KiB, redirect, refused address | transient, reason `anomaly` | same, audited, no token erased |

At `authorize`, a permanent or transient outcome answers code 2 (permanent) or 1 (transient) without writing anything; the `state` being consumed, the operator reruns `reauthorize` (BR-082).
