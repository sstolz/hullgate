# BR-126 · A tool's result is relayed as is, except the value of the connection's token

## Rule

The result that an upstream returns to a `tools/call` (success as well as `isError`) reaches the client with no modification other than the replacement with `[masked]` of every occurrence of the value of the connection's token in its texts; a result that exceeds BR-107's bounds, or the role's effective response cap (`response_cap`, BR-184), is not truncated but replaced with `response_too_large`.

## Clarifications

- This is the "as is, errors included" half of HULL-1 (l. 468); the other half is BR-116 (H11).
- A URL, including the upstream's, present in the content (the link of a Gitea ticket) is business content and remains.
- Masking looks only for the exact value of the connection's token; it does not protect against an upstream that would encode the token differently.
- F-015: the role's cap is measured on the compact JSON of the upstream result, before masking, and its fixed text says the tool ran and its result was withheld (BR-184).
