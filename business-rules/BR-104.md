# BR-104 · SonarQube analyzes only `main`, clean tree

## Rule

`qa-sonar` sends an analysis only if it is called explicitly (`make sonar`, not by `make qa`), the current branch is `main`, the environment supplies `SONAR_HOST_URL`, and the working tree has neither a tracked modification nor an untracked file under `src/` and `tests/`; otherwise it returns `SKIP` with the reason, without calling the server.

## Clarifications

- Reason: in Community, an analysis sent from a branch or a dirty tree replaces the history of `main` with code that is not in it.
- Under `make qa`, the verdict is `SKIP — analyse sur demande : jouer make sonar`: sending a secret to an operator's system remains a named gesture (H6), never a side effect of the aggregator.
- `coverage.xml` is ignored by git: the gate writes, next to it, `coverage.sha` (ignored by git): the SHA of the head it tested, and only if the tree is clean in the sense of the rule (same definition as the guard of `make sonar`, `scripts/qa_tree.py`); on a dirty tree the gate leaves `coverage.sha` absent, so that a dirty gate then canceled does not let through a coverage that is not the head's; if `coverage.xml` or `coverage.sha` is absent, or if that SHA is not the one of `git rev-parse HEAD`, `qa-sonar` returns `SKIP` ("rerun make gate") rather than sending another branch's rate; the scanner receives read-only only `src/`, `tests/`, `sonar-project.properties` and `coverage.xml`, never the whole repository.
- The scanner runs in the `sonar-scanner-cli` image pinned by digest (BR-098); the project key is `hullgate` and the server URL comes from `SONAR_HOST_URL`; unset or empty returns `SKIP` naming it, without a server call. `sonar-project.properties` carries no host.
