# BR-086 · A secret enters through a file, never through an argument

## Rule

The value of a provided token (at `add` as at `reauthorize`), of an application secret or of an authorization return URL is read from a file or from standard input (`--file`, `--secret-file`, `--callback`, with `-` for standard input); a value given as a command argument is refused and is echoed neither in an output, nor in the audit, nor in a log.

## Clarifications

- Neighbor of BR-053 (operator token shown once). The file is the operator's; the session generates no production one (BR-032).
- The CLI runs in the container: the runbook uses standard input (`docker compose exec -T … < jeton.txt`), because the operator's file is on the production server and a secret `docker cp` is fragile under Sysbox (learning F-005). A trailing newline is removed; an empty value is refused (code 2).
- The return URL carries the authorization code (secret value, BR-066): a refusal of `authorize` (unknown `state`, provider `error=`) echoes neither the URL nor the code in the message, the audit or the log.
- In the console a secret enters in the body of a POST, never in a URL, and is never echoed back (BR-213).
