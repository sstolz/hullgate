# BR-070 · The YAML export of the tree is deterministic and secret-free

## Rule

`hullgate export` writes to standard output a YAML of the tree (format version, the organisation's public identifier, levels, names, segments, sensitivity, organisation values and setting overrides) and of the library — services with the names of their tool catalogue and their manual classes, applications (`client_id`, no secret) and connections (name, service, prefix, application, state, placements with their policy) — which, for the same state, is identical byte for byte, and which contains no token, no fingerprint, no inbound OAuth client, no secret, no audit entry, no pinning baseline and no classification queue state.

## Clarifications

- A `format` key (integer, 1 in F-005, 3 since F-010, 4 since F-015, 5 since F-014) opens the document: the import of HULL-11 will read it. The values carried by the organisation are defaults, not overrides (BR-048), but the operator can change them (`settings set / token_duration 60d`): the export carries them so that the import reads them back. If lot A does not emit them, lot B adds them.
- Order: children sorted by segment; keys in a fixed order; internal identifiers excluded. The organisation's public identifier (BR-160) is not an internal one: it is exported as `id`, the first key under `organisation:`, so that a tree restored by import keeps its URLs (F-014); what an import does with it is HULL-11's.
- Spec lines 336-337: the tree is exported as YAML "for backup, review and versioning, and re-imports with a preview of the differences". The import with preview is deferred (HULL-11); from F-005 the export contains everything the import will read back (structure, names, segments, sensitivity, locks, overrides).
- "No OAuth client" targets only the inbound clients of BR-061. A re-import requires re-authenticating the connections (spec lines 682-683): the export carries no token. Services, applications and connections are sorted by name (F-006).
- F-015 (format 4): each placement is a mapping `path`, `mode`, `pin` (`inherit` when the placement carries none), `open`, `deny`, `allowlist`, `pinned_tools` (tool pins), `arguments` (`tool`, `argument`, `values`), every list sorted; each service carries `tools`, its catalogue names sorted, each with its `class` when it has a manual one. Every list entry names a tool the same document carries, so an import on a fresh instance writes the names before the lists that cite them (BR-176). Baselines and queue state are not exported: a re-import pins again (BR-181).
