# BR-018 · The go / no-go table has criteria written in advance

## Rule

Before the first probative test, the bench fixes and commits the go / no-go table: one line per POC hypothesis, at minimum acceptance run 16/16; inbound OAuth; Gitea relay; two generations; maturity of the chosen OAuth building block; API of the chosen MCP SDK; Claude.ai and iOS; measured cost — each with its success criterion and the expected evidence; a criterion changed after the first probative result invalidates the acceptance run, like a policy (BR-011).

## Clarifications

- The evidence of anteriority is the commit SHA recorded in the report and in the results file, not `git log` on `main` (unreadable after a squashed merge, learnings of 2026-10-27).
- Building blocks: Go POC, `fosite` and `go-sdk`; Python POC, `mcp.server.auth` and the `mcp` SDK.
- The Python POC adds two lines: H-9 core requirements (BR-026), H-10 checks outside the acceptance run (BR-025).
