# BR-117 · A call with an uncertain outcome is never replayed

## Rule

When a tool call's request has been sent and the response is missing or incomplete (deadline, cut, interrupted stream), the relay returns `uncertain_outcome` (cut) or `deadline_exceeded` (deadline), according to BR-116, and sends no second request for that call; the relay's only retry is that of a 401 received before any content (BR-127).

## Clarifications

- A write tool whose response is missing may have acted: only the caller decides to replay it (#1, l. 505).
- Failures before sending (resolution, refused TCP connection, TLS) are not replayed either; they return `upstream_unavailable` and the caller decides.
