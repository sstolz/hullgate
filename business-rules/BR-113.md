# BR-113 · `tools/call` finds the connection through the role's table and rechecks before any upstream call

## Rule

A tool call reaches an upstream only if its name is the public name of a tool announced for a connection **placed and active on the role of the URL** at the time of the call, and accepted by the policy; any other name (unknown, of another role, of a connection not placed, absent from the upstream list, hidden or refused by the policy) receives the same "unknown tool" error, without upstream `tools/call`; and every refusal that is decided without an upstream definition (name outside the table, connection not placed on the role, not in state) is decided **before** any `get_access` and any exchange with an upstream.

## Clarifications

- The list the client saw is not an authorisation (#1, l. 465). The chain has two stages (§3.3). **Stage 1**, in the database only, without token or network: name → name table → connection → placement on the role of the URL → state. **Stage 2**: `get_access` → `tools/list` if the cache is cold or stale → name present in the list → policy with definition and arguments → `tools/call`. The policy receives the upstream definition, which exists only after stage 2: a policy refusal therefore costs at most one `get_access` and one `tools/list`, never a `tools/call`.
- The proof by absence (BR-002) reads: 0 upstream `tools/call` for every refusal; 0 exchange and 0 `get_access` for stage-1 refusals; at most one `tools/list` for a stage-2 refusal.
- A name absent from the table never triggers a list fetch. A name present in the table but absent from the fresh list is unknown.
- A call already sent is not interrupted when the placement is removed or the incoming token revoked during its execution: it ends at the latest at the 60 s deadline of BR-107; the following calls are refused (§12).
- A name refused by the policy is indistinguishable from an unknown name (the existence of a hidden tool does not leak).
- A connection placed on a sensitive role reaches stage 2: a listing and a `get_access` happen, no `tools/call` does without an opening (BR-175).
