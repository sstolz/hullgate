# BR-129 · The size of a `tools/call` is bounded before any upstream call

## Rule

A `tools/call` whose arguments, serialized as compact JSON as the relay would send them to the upstream, exceed 1 MiB (1,048,576 bytes) is refused with `request_too_large` before any `get_access` and any exchange with an upstream; no option lifts this bound.

## Clarifications

- BR-107 bounds the bytes read from the upstream, nothing bounded the bytes sent: an authenticated client could have pushed hundreds of MiB to the upstream under one BR-108 slot, in parallel.
- Same ceiling as the read (H6, H19). Reading the raw body of the access point before parsing, for all methods, is not bounded by this rule (§Out of Scope).
- The refusal is stage 0 of BR-113; it is audited (BR-122, outcome `request_too_large`).
- F-020: the raw body read is bounded separately by BR-311 (2 MiB); this rule still bounds compact arguments at 1 MiB.
