# BR-069 · The schema migrates forward at startup, or the gateway is not ready

## Rule

At startup, the gateway applies in order, each in its own transaction, the migrations whose number exceeds the schema version of the database; a failing migration leaves the database at the last successful version and the gateway not ready (`/readyz` 503 `schema_error`), and a database of a version newer than the code is not modified and makes the gateway not ready (`schema_too_new`).

## Clarifications

- Version held by `PRAGMA user_version`; forward migrations only, never modified once published.
- The CLI refuses to act on a database whose version differs from that of the code (code 1, message).
- `make restore-check` (BR-039) restores a backup of an earlier version: the migration plays there in the throwaway container.
