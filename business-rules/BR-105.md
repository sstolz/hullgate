# BR-105 · The SonarQube token never leaves its file or the scanner's environment

## Rule

`qa-sonar` reads the token from `SONAR_TOKEN`, or the file named by `SONAR_TOKEN_FILE` and passes it only to the scanner, through an environment variable (`SONAR_TOKEN`); the value appears neither as a command argument, nor in the `make` output, nor in a tracked file, nor in a log.

## Clarifications

- With neither token input set, `SKIP` names `SONAR_TOKEN` and `SONAR_TOKEN_FILE`; an unreadable or empty file also skips; a refused token (401) is an `ERROR` that says to renew it, without quoting it (§3.2).
- `.cairn/auth/` is ignored by git (already in place); `.scannerwork/` joins `.gitignore`.
- A leak is not allowed: no waiver (`strict` rule); a token value found in an output, an argument or a tracked file is an error of the test `test_br_105_qa_sonar_token.py`, hence of the gate.
