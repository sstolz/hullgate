# BR-020 · The Claude.ai and iOS operator step is traced, never simulated, and delivered as copy-paste runbooks

## Rule

The deliverable contains, for each operator path (Claude.ai web, Claude iOS), a copy-paste runbook in `docs/runbooks/` (one file per path: `poc-go-claude-ai.md`, `poc-go-ios.md`), which covers exposing the gateway over HTTPS (public URL or tunnel), adding the connector, calling `ping`, observing the token renewal and reading the verdict; each step is a command block or a value to paste, ready to use (URL, `client_id`, scopes, POC and tunnel launch commands), with the expected result, the course of action if the result differs, and reporting the result on HULL-3; as long as the operator has not reported their result, the table line stays "awaiting operator" and never becomes « réussi » on bench evidence. The report points to these runbooks.

## Clarifications

- The session opens no tunnel or public URL, and asks for no Claude account; it writes the commands and the values, the operator runs them.
- No real token, secret or key in a runbook: a secret value is a named slot that the operator fills (BR-003, bench scan extended to the runbooks).
- A failure reported later reopens the verdict via HULL-3 if the defect lies in the OAuth implementation (not the client).
- For a following POC (Python POC), the runbooks of a previous POC hold if the operator values are identical — access point paths, `client_id`, scopes, redirect URI, authorization secret variable, public port; the report then gives the new POC's launch block ready to paste, its expected result and its course of action if the result differs, and points to the runbooks for the other steps. A single different value requires two runbooks of their own (`docs/runbooks/poc-python-claude-ai.md`, `poc-python-ios.md`). The comparison of the values appears in the report.
