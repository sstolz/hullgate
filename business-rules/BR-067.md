# BR-067 · The MCP access point of a role serves the protocol and the relay's tool list

## Rule

After the authorization order, the access point serves stateless MCP through the SDK for versions 2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25 and 2026-07-28, answers `ping` in every version that defines it, returns the tool list that the relay builds for the role of the URL (BR-109) and routes every tool call to it (BR-113), a name outside the list remaining an unknown tool; a version not served receives 400 whose `error.data.supported` lists the five versions.

## Clarifications

- The tool list is the relay's (F-008, BR-109); a role with no placed and active connection, or whose upstreams announce nothing, returns the empty list as in F-005; the access point stays stateless and never issues a `Mcp-Session-Id`.
- The pinned SDK (2.3.0) defines `ping` only for the four handshake versions; in 2026-07-28 the method answers `-32601`, and the version is proved by `server/discover`, `tools/list` and `tools/call` (lot A, §9). Any probe "by the `ping` method" therefore sends a handshake version (v1 bench, BR-071).
- The glue for `supported` (12 lines in the POC) is written as an explicit extension, not as a replacement of an object of the module.
