# BR-044 · The tree has five fixed levels and one URL per role

## Rule

The tree (spec lines 138-139, 210-214) has a root organisation, then exactly the levels client, project, environment and role, each node having as parent only a node of the immediately higher level; each role is served at the URL `${PUBLIC_URL}/o/<id>/p/<client>/<project>/<env>/<role>/mcp`, `<id>` being the organisation's public identifier (BR-160). A creation, rename or move that would violate the level, the segment format or the uniqueness of the segment among siblings is refused with a message naming the constraint, writing nothing.

## Clarifications

- Segment: `^[a-z0-9]+(-[a-z0-9]+)*$`, 1 to 40 characters (H3); display name: 1 to 80 characters, without control characters. An empty derived segment is refused (no silent fallback to `x` as in the prototype).
- Uniqueness among siblings only: `acme/api` and `mpx/api` coexist.
- No reserved segment: the prefix `/o/<id>/p` separates the access points from the technical routes (`/.well-known`, `/admin`, `/healthz`, `/readyz`), spec lines 216-217.
- Creating an environment creates with it a `principal` role (spec lines 188-189); it is renamed or deleted like any role.
- A single organisation per instance (H2), created by the first migration, display name modifiable, without a segment: `<id>` is not a segment and `--path` values never carry it; it is not deleted (refusal, code 2).

## Examples

### Example 1

- **Given** the project `mpx/cairn` has an environment `prod`
- **When** the operator adds under `mpx/cairn` an environment named "Prod"
- **Then** the derived segment `prod` is already taken: refusal "segment already used under mpx/cairn: prod", code 2, nothing written.
