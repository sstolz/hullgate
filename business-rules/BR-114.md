# BR-114 · The upstream token comes from `get_access` alone

## Rule

The only secret the relay presents to the upstream is the one that `get_access(connexion, rôle de l'URL)` returns, never the client's (BR-022); a typed error of `get_access` becomes a closed code of BR-116 without upstream exchange.

## Clarifications

- Retrying after a 401 is rule BR-127, separate: a relay that replays twice with the right token complies with this one and violates the other.
- The relay never renews by itself (F-006 §3.3) and never presents the client's token (BR-022).
- `access_not_placed` (race with a placement removal) returns "unknown tool"; `access_not_authorized`, `access_reauth_required` return `connection_reauth_required`; `access_temporarily_unavailable(retry_after)` returns `upstream_unavailable` with the delay; `access_key_unavailable` cannot happen here (the access point has already answered 503, BR-064) and, if it occurs, returns `upstream_unavailable`; `access_integrity_error` returns `upstream_unavailable` (already audited by F-006).
