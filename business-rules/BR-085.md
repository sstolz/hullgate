# BR-085 · A provided-token connection is never renewed

## Rule

A provided-token connection keeps its value encrypted like any connection, is never renewed, goes to `réauthentification requise` only if the provider refuses it, and changes value only through `connection reauthorize <c> --file <f|->`, which replaces the encrypted value while keeping name, prefix and placements and sets it back to `active`.

## Clarifications

- **Operator addition, outside specification HULL-1** (decision A2, 2026-10-29): fallback if a provider refuses an OAuth token.
- The provider's refusal arrives through `signal_refusal` (§3.3), called by HULL-9 on an upstream 401: one signal of the current generation is enough. Until HULL-9, only the tests call it (AC-14).
- Value replacement (operator decision of 2026-10-29, Q1 a, stress-test M16): from `active` or `réauthentification requise`; the value is read from a file or standard input (BR-086), the old one is erased in the same transaction, `generation` is incremented (a `signal_refusal` for the old value is ignored), and the event is audited without the value (BR-066 v2). The labeled account (`--account`) can be changed in the same command. `--file` on an OAuth connection, or without `--file` on a provided connection: code 2.
