# BR-182 · Only the operator validates a change, after reading it

## Rule

`tool diff` shows, for each suspended, new or removed tool of the subtree, the fields that changed, old and new; `tool validate` alone records the current definition as baseline and lifts the suspension, for the whole connection or for one `--tool`.

## Clarifications

- No access point, relay path or client action can validate.
- `tool diff` lists the upstream at reading time and prints upstream text with control characters and terminal escape sequences escaped: the text comes from the party pinning distrusts.
- `tool validate` re-reads the upstream: it validates what is there now, not what the last diff showed, and prints the hashes it recorded.
- An upstream that does not answer during `tool diff` or `tool validate`: exit 2, nothing written, the same posture as `policy arg`.
- `tool diff` states: `suspended`, `changed` (the current definition differs from the baseline, no listing has suspended it yet), `new`, `removed`. Values are escaped one-line JSON; `--json` is ASCII-only, DEL escaped.
- `tool validate` lists the upstream once per connection, takes catalogue names only, and is refused before any exchange when a role of the connection's placements in the subtree lies under a lock; `--tool` names a tool that is pinned or holds a row, else exit 2.
- A stored row that cannot be loaded makes `tool diff`, `tool validate`, `policy show`, `policy arg`, `connection tools` and `export` answer a policy error naming the connection, exit 1, nothing written. An upstream definition UTF-8 cannot encode reads as a change in `tool diff`; `tool validate` refuses it, nothing written, and validates the other tools with `--tool` (lot B review, N2); `policy arg`, whose rule baselines its tool at entry, refuses it the same way (lot C review, N1).
- a field whose value changed between a string and a non-finite number of the same spelling carries a type mark in `tools/diff`, and SCR-10 shows it; `docs/admin-api.md` says so (review 8, N7).
