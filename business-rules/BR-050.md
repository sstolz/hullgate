# BR-050 · A token covers its node and its descendants, segment by segment

## Rule

A token placed on a node N is accepted on a role R only if N is R or an ancestor of R in the tree; a token placed elsewhere is refused, even if N's path is a textual prefix of R's.

## Clarifications

- The comparison follows the tree's identifiers (equivalent to a whole-segment prefix): a token placed on `mpx/cai` does not cover `mpx/cairn/…`.
- An OAuth access token is placed on its access point's role and covers only it.
- An operator token is placed on any node, organisation included (root token `*`, spec lines 356-357: all clients outside sensitive environments, "reserved for administration, not recommended for an agent"); the CLI asks for `--confirm '*'` for the root token and the audit marks it; the organisation is designated by `--path /`.
- Tokens under the role (connection + mode, spec lines 370-371) and tokens reduced to a mode (spec line 351): out of scope (HULL-8, HULL-10).
