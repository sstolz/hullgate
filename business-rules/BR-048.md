# BR-048 · Settings are inherited, with their origin

## Rule

The effective value of a setting on a node is that of the nearest override going up from the node to the organisation, which carries the default value of each declared setting; every read of a setting returns the effective value and the origin node.

## Clarifications

- `unset` removes the node's override (restoring inheritance); on the organisation, `unset` is refused (the root always carries a value).
- Settings declared by F-005: `token_duration` (duration `<n>h` or `<n>d`, 1 h to 365 d, default `30d`) and `lock` (BR-049 specifies its effect). An undeclared key or an out-of-format value is refused.
- A setting change is an audit event with old and new value.
- Settings declared by F-015 (BR-177, BR-180, BR-184): `mode` (`read`, `write`, `destructive`, default `write`), `pinning` (`auto`, `on`, `off`, default `auto`) and `response_cap` (`<n>KiB` or `<n>MiB`, from 1 KiB to 1 MiB, default `1MiB`); migration 7 writes their organisation defaults.
- F-020: `token_rate_limit` and `connection_rate_limit` are declared settings, form `<n>/min`, 1 to 100000, defaults `120/min` and `300/min` at the organisation.
